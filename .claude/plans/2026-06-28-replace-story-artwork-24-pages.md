# Plan: Replace story artwork with the new image set (21 → 24-page restructure)

## Context

The user delivered a fully re-illustrated image set at the repo root — `images/`
(`1.png`–`25.png`) and `mini-images/` (`Frame 1.png`–`Frame 22.png`) — and wants the
app to use it instead of the current artwork. The new set re-paginates the story and
adds two new content pages, so this is an **asset swap plus a small data-layer
restructure** (not a code/UI change).

New source → role (verified by viewing the images):
- `images/1.png` — home cover (the title art "Misi Penjaga Budaya dari Menoreh")
- `images/2.png` — "Tokoh" character-intro page (Bu Rini, Dimas, Rara, Bagas, Pak Wiryo, Jaya)
- `images/3.png … 24.png` — 22 comic story pages, "Halaman 1 … Halaman 22"
- `images/25.png` — "Glosarium" (cultural-terms glossary)
- `mini-images/Frame N.png` (N = 1..22) — picker thumbnail for comic "Halaman N"

Confirmed decisions (this session):
- **Tokoh** becomes the **opening navigable page** (page 1).
- **Glosarium** becomes the **final navigable page**.
- **Narration**: best-effort — reuse existing `narasi-N.mp3` by Halaman number, silent where missing.
- **Images optimized to 1280×720** (the stage's native size) to shrink the APK.

Result: story grows 21 → **24 navigable pages** — Tokoh (1), Halaman 1–22 (pages 2–23),
Glosarium (24). The home cover and the quiz are unchanged in flow.

## Page / asset mapping

Page number = (source image number − 1). Backgrounds keep the existing `pageN.png`
convention so nothing downstream needs new path logic.

| Page | Title | Background ← source | Thumbnail ← source |
|---|---|---|---|
| —  | (cover)        | `page-cover.png` ← `images/1.png`  | — |
| 1  | Halaman Tokoh  | `page1.png`  ← `images/2.png`      | `mini-page1.png`  ← generated from `images/2.png` |
| 2  | Halaman 1      | `page2.png`  ← `images/3.png`      | `mini-page2.png`  ← `Frame 1.png` |
| 3  | Halaman 2      | `page3.png`  ← `images/4.png`      | `mini-page3.png`  ← `Frame 2.png` |
| …  | …              | `page(K-1).png` ← `images/K.png`   | `mini-page(N+1).png` ← `Frame N.png` |
| 23 | Halaman 22     | `page23.png` ← `images/24.png`     | `mini-page23.png` ← `Frame 22.png` |
| 24 | Glosarium      | `page24.png` ← `images/25.png`     | `mini-page24.png` ← generated from `images/25.png` |

Note the **+1 offset on thumbnails**: Tokoh shifts the comics by one page, so comic
"Halaman N" is page `N+1` and uses `Frame N.png` → `mini-page(N+1).png`. Tokoh and
Glosarium have no `Frame` export, so their thumbnails are generated by downscaling
their full art to 304×202 (the existing Frame size); they will lack the decorative
frame/“Halaman N” label the `Frame*.png` files have — a minor cosmetic difference only.

## Steps

### 1. Process & place images (throwaway shell script in scratchpad, ImageMagick `convert` — already available)
- **Spot-check first**: confirm the sequence is contiguous (e.g. `images/13.png` reads
  "Halaman 11", `images/3.png` = "Halaman 1", `images/24.png` = "Halaman 22") before
  trusting the `image K → Halaman (K-2)` mapping.
- **Backgrounds** (downscale, strip metadata, keep PNG):
  `convert images/K.png -resize 1280x720 -strip -define png:compression-level=9 public/assets/img/page(K-1).png`
  for K = 2..25, plus `images/1.png → public/assets/img/page-cover.png`.
  (Source is 1920×1080 16:9 → exact 1280×720, no distortion.)
- **Comic thumbnails**: copy `mini-images/Frame N.png → public/assets/img/mulai/mini-page(N+1).png`
  (already 304×202, ~130 KB each — no re-encode).
- **Generated thumbnails**: `convert images/2.png -resize 304x202! … mini-page1.png`
  and `convert images/25.png -resize 304x202! … mini-page24.png`.
- **Remove the orphan** `public/assets/img/page-tokoh.png` (currently unreferenced;
  the new `page1.png` supersedes it — avoids a redundant ~MB in the APK).
- **Measure & report** the resulting `public/assets/img` size (expected below the
  current 66 MB, well below the 94 MB raw source).

### 2. Regenerate the data layer — `src/data/slides.ts`
Replace `SLIDES` with 24 entries (interface, `STAGE`, `slideByPage`, `PAGE_COUNT`
helpers all unchanged):
- **page 1**: title `'Halaman Tokoh'`, `assets/img/page1.png`, backsound `null`.
- **pages 2–23**: titles `'Halaman 1' … 'Halaman 22'`, `page2.png … page23.png`.
  - backsound, best-effort by Halaman number (files present: 1,2,4,5,10,11,12,13,14,15):
    Halaman 1→`narasi-1`, 2→`narasi-2`, 4→`narasi-4`, 5→`narasi-5`, 10→`narasi-10`,
    11→`narasi-11`, 12→`narasi-12`, 13→`narasi-13`, 14→`narasi-14`, 15→`narasi-15`;
    Halaman 3, 6, 7, 8, 9, 16–22 → `null` (no matching file).
- **page 24**: title `'Glosarium'`, `assets/img/page24.png`, backsound `null`.

### 3. Verify
- `npm run type-check` and `npm run build` — clean.
- `npm run dev`, visually check:
  - Home cover shows the new title art.
  - Mulai picker shows **24 thumbnails across 4 pages** — Tokoh first, Glosarium last;
    generated thumbs render; no broken `mini-pageN.png`.
  - `/slide/1` = Tokoh, `/slide/2` = "Halaman 1", `/slide/23` = "Halaman 22",
    `/slide/24` = Glosarium.
  - Prev off page 1 → home; **Next off page 24 → quiz** (`/kuis`), per
    `SlideView.go()`.
  - Audio control toggles where narration exists; silent (but still toggleable UI)
    where `backsound` is `null`.

## Files
- modify: `src/data/slides.ts`
- replace (assets): `public/assets/img/page-cover.png`, `public/assets/img/page1.png … page24.png`,
  `public/assets/img/mulai/mini-page1.png … mini-page24.png`
- delete (asset): `public/assets/img/page-tokoh.png` (orphan)
- **no Vue component edits** — navigation (`SlideView.go`), the `/slide/:n` route,
  prev/next chain, and the Mulai picker (`MulaiGrid` iterates `SLIDES`) are all
  data-driven and absorb the new count automatically.

## Notes / risks
- The `images/` and `mini-images/` source dirs at the repo root are not used by the app
  at runtime; after the swap they can be deleted or left in place (the swap reads from
  them, doesn't reference them).
- If 1280×720 PNG is still larger than wanted, a follow-up could re-encode backgrounds
  as high-quality JPG/WebP — but that requires updating the `.png` paths in `slides.ts`,
  `HomeMenu.vue`, and `QuizView.vue`, so it's deferred to keep paths stable now.
- Generated Tokoh/Glosarium thumbnails won't carry the decorative frame/label of the
  `Frame*.png` exports — cosmetic only.
- Per the global plan-file rule, a copy of this plan will be mirrored to the repo's
  `.claude/plans/` during implementation (this file is the plan-mode working copy).
